# Unit Net Cap

Консольная утилита для учёта и автоматического ограничения месячного сетевого трафика системных служб и Docker-контейнеров на Ubuntu Server / Linux.

## ✨ Особенности и возможности

- Учёт трафика служб `systemd` и контейнеров `docker`;
- Автоматическое управление по объёму трафика;
- Защита от перезагруки устройства и ручного включения программ;
- Автосброс раз в месяц;
- Защита критических служб от добавления в учёт;
- Интерактивный TUI-интерфейс;
- Поддержка CLI-команд.

## 🚀 Установка, обновление и удаление

### Установка и Обновление
Для установки или обновления утилиты на Ubuntu Server выполните следующую команду с правами `root`:
```bash
curl -fsSL https://raw.githubusercontent.com/InstalerUP/unit-net-cap/main/install.sh | sudo bash
```
<details>
  <summary><b>Что делает скрипт установки</b> <code>install.sh</code>:</summary>

  - Проверяет наличие прав суперпользователя и интерпретатора `Python 3`.
  - Предоставляет выбор ветки проекта (по умолчанию `main`).
  - Скачивает актуальную версию репозитория (или использует локальную директорию).
  - Копирует файлы пакета в `/usr/local/lib/unit-net-cap/unit_net_cap`.
  - Создает исполняемую точку входа `/usr/local/bin/netcap`.
  - Устанавливает системный `systemd`-сервис `netcap.service` в `/etc/systemd/system/netcap.service`.
  - Запускает и активирует фоновый демон через `systemctl enable --now netcap.service`.
</details>

### Удаление
Чтобы удалить утилиту и очистить систему от её работы выполните:
```bash
sudo bash /usr/local/lib/unit-net-cap/unit_net_cap/install.sh --uninstall
```

## ⌨️ Описание CLI-команд
- `netcap status` — просмотр статуса приложений и трафика.
  - `--json` — вывести текущее состояние в формате JSON.
  - `--all-interfaces` — показать все сетевые интерфейсы без фильтрации.
- `netcap add <name> --limit <GB>` — добавление объекта в мониторинг.
  - `--limit <float>` — месячный лимит в гигабайтах (`0` активирует режим мониторинга).
  - `--type <systemd|docker>` — тип объекта (если не указан, определяется автоматически).
  - `--mode <both|egress|ingress>` — режим подсчета (`both` — входящий + исходящий, `egress` — исходящий, `ingress` — входящий).
  - `--no-restart` — не перезапускать активную системную службу сразу после применения.
- `netcap set <name>` — изменение параметров существующего объекта.
  - `--limit <float>` — месячный лимит в гигабайтах (`0` активирует режим мониторинга).
  - `--mode <both|egress|ingress>` — режим подсчета (`both` — входящий + исходящий, `egress` — исходящий, `ingress` — входящий).
- `netcap remove <name>` — удаление объекта из мониторинга.
- `netcap reset <name>` — сброс счетчика трафика.
  - `--all` — сбросить для всех.
- `netcap config` — просмотр и изменение параметров (без аргументов выводит текущую конфигурацию)
  - `--interval <sec>` — интервал опроса затраченого трафка (`30` – `10800` в секундах).
  - `--default-mode <both|egress|ingress>` — режим подсчета по умолчанию для новых объектов.
  - `--reset-day <1..28>` — день месяца для автоматического сброса счетчиков.
  - `--interface-view-mode <main|all>` — режим отображения системных интерфейсов.
  - `--add-iface <name>` — всегда показывать указанный сетевой интерфейс в `main` виде.
  - `--remove-iface <name>` — удалить интерфейс из списка всегда видимых в `main` виде.
- `netcap daemon` — запуск фонового демона (запускается автоматически).
- `netcap uninstall` — удаление программы, остановка службы и восстановление всех заблокированных квотой служб и контейнеров (требуется `sudo`).

### Используемые технологии
- **Язык:** Python 3 (без сторонних `pip`-пакетов).
- **Системные интеграции:** 
  - systemd (управление службами через `systemctl`, парсинг счетчиков через `systemctl show`, drop-in директории).
  - Docker Engine API (через CLI-команды `docker stats` и `docker inspect` / `docker update`).
  - Сетевые интерфейсы Linux (`/proc/net/dev`).
- **Формат хранения данных:** JSON.

### Системные требования
- **Операционная система:** Linux (протестировано на Ubuntu Server / Debian-подобных дистрибутивах).
- **Права:** Требуются права суперпользователя (`root` / `sudo`) для управления службами systemd, настройки IPAccounting и Docker-контейнеров.

### Зависимости
Проект разработан **без внешних сторонних зависимостей**:

1. **Python 3** (версия 3.8 или выше) — *встроен в ОС / репозитории Ubuntu*.
2. **systemd** — *стандартная система инициализации в Ubuntu / Debian*.
3. **Docker Engine** (опционально, требуется только если вы планируете мониторить и ограничивать трафик Docker-контейнеров).
4. **Стандартные модули Python 3** (`argparse`, `json`, `pathlib`, `shutil`, `signal`, `subprocess`, `time`, `datetime`, `os`, `sys`).

### Архитектура и как это работает

1. **Мониторинг интерфейсов (`net_proc.py`):**
   Демон периодически читает `/proc/net/dev`, замеряя входящий (`RX`) и исходящий (`TX`) трафик по всем сетевым интерфейсам (с возможностью фильтрации виртуальных/мостовых интерфейсов).
2. **Учёт трафика `systemd` (`systemd_ctrl.py`):**
   При добавлении службы утилита создает файл `/etc/systemd/system/<unit>.d/netcap.conf` с директивой `IPAccounting=yes`. После перезагрузки службы systemd начинает вести учет сетевых пакетов и байтов для данного юнита, которые считываются через `systemctl show`.
3. **Учёт трафика Docker (`docker_ctrl.py`):**
   Демон вызывает `docker stats --no-stream --format json`, получая текущие суммарные сетевые счетчики (`net_input`, `net_output`) для каждого запущенного контейнера.
4. **Фоновый демон (`daemon.py`):**
   Работает в непрерывном цикле с настраиваемым интервалом. Вычисляет дельту трафика с момента последнего опроса, прибавляет к месячному счетчику, сохраняет состояние в `/var/lib/unit-net-cap/state.json` и проверяет лимиты.

### Файлы конфигурации и состояния

- **Файл состояния и статистики:** `/var/lib/unit-net-cap/state.json`
- **Конфигурация systemd юнита демона:** `/etc/systemd/system/netcap.service`
- **Drop-in файлы учета служб:** `/etc/systemd/system/<unit>.d/netcap.conf`
